# Active Directory・横移動プレイブック

攻防戦形式の演習で内部ネットワークにActive Directory環境がある場合の定番アプローチ。単一ホストの侵害で終わらせず、ドメイン内の他ホスト・より高い権限に広げる段階。

## まず全体像を把握する(列挙)
- ドメインコントローラのIP、ドメイン名を特定(`nslookup`, DNS SRVレコード, SMB経由の情報から)
- 匿名/低権限でどこまで見えるか: `enum4linux -a <dc>` や `rpcclient -U "" <dc>` でユーザー一覧・グループ・ポリシーを列挙できないか
- 認証情報(ドメインユーザーの1つでも)を得たら BloodHound 的な考え方で「今のユーザーから最短でDomain Adminに到達する経路」を意識して列挙する

## Kerberoasting
- サービスアカウント(SPNが設定されたアカウント)のKerberosチケットは、そのアカウントのパスワードハッシュで暗号化されている
- 認証済みの低権限ドメインユーザーであれば、SPN一覧を取得してチケットを要求し、オフラインでハッシュを解析(hashcat/john)できる
- サービスアカウントは強度の低いパスワードのまま放置されがちなので成功率が高い定番手法

## AS-REPRoasting
- 「事前認証を要求しない」設定(`Do not require Kerberos preauthentication`)のアカウントは、パスワードを知らなくてもASリクエストを送るだけでハッシュ付きの応答が得られ、オフラインクラックが可能
- 該当設定のアカウントがないか列挙して確認する

## Pass-the-Hash / Pass-the-Ticket
- NTLMハッシュそのもの(平文パスワード不要)を使って別ホストに認証できる場合がある(Pass-the-Hash)
- Kerberosチケット(TGT/TGS)を盗んで使い回すことも同様に可能(Pass-the-Ticket)
- ローカル管理者パスワードの使い回し(複数ホストで同一のローカル管理者パスワード)は、1台の侵害から横展開する典型的な経路

## DCSync
- ドメインコントローラへのレプリケーション権限(通常はDC自身やDomain Admin相当)があると、パスワードハッシュを含むAD全体のデータを「レプリケーションのふり」をして取得できる
- 到達できたら実質的にドメイン全体の制圧に近いので severity は最上位

## 横移動の基本方針
- 1台侵害 → その端末に残っている認証情報(メモリ上・設定ファイル・ブラウザ保存等)を確認 → 別ホストで使い回せないか試す、を繰り返す
- 到達可能なホスト一覧・共有フォルダ・信頼関係(ドメイン間trust)も横移動の経路になる

## 報告
- 列挙段階の発見は report(recon, ...)
- 認証情報・チケットの取得は report(exploit, ...)
- Domain Admin相当への到達、DCSync成功などは report(finding, severity="critical")
